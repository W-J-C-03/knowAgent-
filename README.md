# KnowAgent 基于LangGraph的RAG‑Agent Demo
> ⚠️ 本仓库为**学习演示项目**，**并非开箱即用生产部署版本**。
> 仓库内仅保留核心业务逻辑代码，剥离了敏感密钥、本地环境配置、完整Web服务、持久化调度等附属代码；整套系统在本地开发环境完成端到端验证，适合学习 LangGraph 编排、RAG多路召回、MCP工具调用思路。

## 技术栈
Python、LangGraph、LangChain、Milvus、Qdrant、MCP（Model Context Protocol）

## 主要实现
1. 基于 `StateGraph` 搭建**双Agent独立工作流**：文档导入Agent、问答检索Agent，职责解耦。导入流负责文档解析、分块、向量化入库；问答流负责用户意图识别、检索分支调度、工具调用、答案生成。
2. 使用 `TypedDict` 定义结构化状态，搭配 Reducer 函数处理并发场景下的状态字段合并、避免节点并行执行时发生状态覆盖、数据丢失，保证状态流转可靠。
3. 多路召回策略：原生向量检索 + HyDE（假设文档增强检索） + MCP标准化联网工具调用三路召回；采用 RRF 算法对多源结果融合、去重、加权排序，兼顾私有知识库信息与外部实时信息。
4. 支持多轮对话实体消歧与指代改写：读取历史对话上下文，识别模糊提问、代词指代；利用 LangGraph 条件边实现动态路由，可根据判断分支选择：直接回答、触发检索、反问用户澄清、调用联网工具。
5. 状态机可观测：每个节点独立输出中间状态，便于调试链路中切片、召回、工具调用、重排各个环节的中间结果，适合学习排错。

## 关键模块
- `graph/`：存放两套 StateGraph 定义，包含节点函数、条件路由逻辑、状态Reducer配置；分为导入图、问答图两个子图。
- `retriever/`：召回核心实现，包含向量检索封装、HyDE 问题增强、RRF融合打分、结果过滤逻辑，适配 Milvus/Qdrant 切换。
- `utils/`（补充）：文档切片工具、实体提取、prompt模板、日志打印等通用辅助函数。

## 运行说明
1. 代码仅为核心逻辑，需要自行配置 Milvus / Qdrant 向量服务、LLM API、MCP Server
2. 可单独调试 graph 内每个节点，支持分步测试，不需要一次性跑完整链路
3. 不包含鉴权、限流、持久化、前端页面，不建议直接用于线上业务
